# 文件寫作規範

Writing standard for repo-internal documents and agent replies. Written in Traditional Chinese (Taiwan) because that is what it governs.

適用對象：`specs/`、`.agents/docs/`、`README.md`、`ARCHITECTURE.md` 等 repo 內部文件，以及 agent 在對話中對 owner 的回覆。不管 blog 文章（`packages/articles/`）與 commit / PR 說明，那兩類另有自己的慣例。

底層依據是 `.agents/skills/iso-24495-skill`（ISO 24495-1 淺白語言，含中文手法層）。四原則（相關、找得到、看得懂、用得上）與中文手法照該 skill 走，本檔不重複；本檔只加這個專案自己的三條約束：版面節制、台灣軟體圈用語、專業度。

`specs/` 底下的 spec 與 plan 另有結構規定，見 [specs/README.md](../../specs/README.md)。

寫長文件或改寫既有文件前先讀該 skill 的 `references/chinese-techniques.md`；短回覆直接套本檔的自查清單即可。

## 一、版面節制

Markdown 符號用來承載結構，不是用來加強語氣。符號一多，讀者就分不出哪裡真的重要。

- 不用 emoji，不用裝飾性圖示。狀態標記例外：計畫表格裡的 ✅ / ⬜ 是資料，不是裝飾。
- 粗體一段最多一處，只圈那一句真正的關鍵詞；不要整句或整段粗體。斜體不用。
- 不用 blockquote 當強調。blockquote 只放真正的引文或「為什麼這樣做」的旁註。
- 條列給三項以上真正並列的東西。只有兩項就寫成一句話，用頓號或分號連。
- 步驟一律編號；並列項目才用 `-`。
- 標題最多到第三層。需要第四層代表這個章節該拆成獨立檔案。
- 不用水平線 `---` 分段，不用驚嘆號，不用全大寫當強調。
- 不用刪除線保留舊內容。文件只寫現況，改掉就直接覆寫；歷史查 git，理由若還有用就改寫成一句現在式的事實。
- 表格只放欄位一致的對照資料。要講理由的內容寫進正文，不要塞進表格欄位。
- 程式碼識別字、檔名、路徑、指令一律 inline code；連續多行指令用 code fence 並標語言。

## 二、台灣軟體圈用語

判準分三類：

1. 程式碼識別字、指令、檔名、套件名、工具名、協定名：一律保留原文，包在 inline code 裡。`transpilePackages`、`pnpm install`、Storybook、Radix、OKLCH 都不翻。
2. 已有台灣通行譯法的概念詞：用中文。元件、相依套件、建置、部署、快取、佇列、型別、介面、程式碼、資料、效能、最佳化、預設值、匯入、匯出、變數、函式、陣列、字串、分支、合併、提交。
3. 沒有通行中文、或翻了反而更難懂的詞：保留原文，第一次出現時用括號補一句白話，之後直接用。

中文、英文、數字之間留一個半形空格（「跑 3 個 story」）；inline code 前後不另加。中文標點用全形。

嚴禁大陸用語。常見誤用對照：

| 大陸用語 | 台灣用語 |
| --- | --- |
| 组件 | 元件 |
| 构建 | 建置 |
| 服务器 | 伺服器 |
| 内存 | 記憶體 |
| 缓存 | 快取 |
| 数组 / 字符串 | 陣列 / 字串 |
| 函数 / 接口 / 类型 | 函式 / 介面 / 型別 |
| 优化 / 默认 | 最佳化 / 預設 |
| 代码 / 软件 / 硬件 | 程式碼 / 軟體 / 硬體 |
| 网络 / 数据 / 信息 | 網路 / 資料 / 資訊 |
| 视频 / 鼠标 / 屏幕 | 影片 / 滑鼠 / 螢幕 |
| 质量 | 品質 |

特別注意「文件」：在台灣指 document，指 file 時要寫「檔案」。

## 三、專業度

- 只寫查證過的事實。結論後面附機械證據：指令與其輸出、`檔案:行號`、commit hash、日期。
- 沒跑過就不要寫成跑過。推測寫成推測，並說出還缺哪一步才能確認。
- 不寫行銷語（強大、完美、極致、革命性、大幅提升），不誇自己的產出。
- 不寫空的收尾段。「總而言之」「綜上所述」開頭的段落多半可以整段刪掉。
- 每個決策記日期與理由；改掉舊決策時，說清楚推翻的是哪一條。
- 保留誠實的不確定（「可能」「預計」承載真實資訊），刪掉裝飾性的堆疊。

## 四、對話回覆的加強條款

同一套規則，另加三條：

- 先給答案或結論，理由放後面。owner 通常只讀前三行。
- 報告工作結果時，做了什麼與沒做什麼都要說；沒做的部分講原因。
- 不要為了看起來完整而重述 owner 已經知道的背景。

## 自查清單（送出或存檔前掃一遍）

1. 結論在不在前三行？
2. 粗體、emoji、blockquote 有沒有超過本檔允許的用法？
3. 有沒有大陸用語？有沒有把 file 寫成「文件」？
4. 該用中文的概念詞有沒有留成英文？該保留原文的識別字有沒有被硬翻？
5. 每個「已完成」「已驗證」後面有沒有附證據？
6. 有沒有整段刪掉也不損失資訊的內容？
